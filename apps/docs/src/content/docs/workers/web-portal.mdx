The worker portal is your schedule in a browser. It signs you in with an emailed code, not
a password.

## Do it

<Steps>
  <li>
    Open the portal in any browser and type your Penn email under <UI>Email</UI>.
    <span class="step-note">Your manager creates your account. There is no sign up.</span>
  </li>
  <li>Choose <UI>Send code</UI>.</li>
  <li>Open the email and read the 6 digit code.</li>
  <li>
    Type it under <UI>Code</UI>, then choose <UI>Verify and sign in</UI>.
  </li>
</Steps>

## What you'll see

Your schedule, the same one the app shows. Both surfaces read one calendar, so a drop,
claim or swap on either side lands on both.

## Rules that apply

- **Type the code on the machine you want to use.** A link would sign in your phone, not
  the desk computer, so the email sends digits. See [Signing in](/workers/signing-in).
- **Your role decides what you see, not the browser.** A code session carries the access
  your account already has. See [Roles and the duty hierarchy](/system/roles).
- **Your phone still does the alerting.** Web has less notification support and no widgets,
  so keep the app for floats and openings. See
  [What triggers a notification](/system/notifications-rules).

## If it goes wrong

**No code arrives.** An address with no account gets none, because nobody can sign
themselves up here. Ask your manager.

**The code is refused.** Choose <UI>Resend code</UI> and type the newest one. Choose
<UI>Use a different email</UI> if you mistyped the address.

**A password reset sends you back to sign in.** The web has no password to reset. The app
still does.
