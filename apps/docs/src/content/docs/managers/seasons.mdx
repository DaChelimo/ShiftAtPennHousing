A season sets which houses are open on which summer dates, each desk's headcount, and
floating windows. Only an Administrator authors one, across every house.

<Callout label="Publishing cancels people">
  Your edits sit in a draft until you publish.

  Cut a desk's headcount and the extra workers are cancelled and notified. The order is
  fixed: floaters first, then whoever holds the fewest blocks there.

  Reopening a house later returns empty seats, not those workers' shifts.
</Callout>

## Do it

<Steps>
  <li>
    In <UI>Operations</UI>, open a season or <UI>Create a season</UI>.
  </li>
  <li>
    Set the preference deadline.
    <span class="step-note">
      One value, on or before the season's start date.
    </span>
  </li>
  <li>
    Per house, add a window: dates, then weekday and weekend bands.
    <span class="step-note">
      A band is a time range plus a headcount. Empty bands close the house.
    </span>
  </li>
  <li>Add the windows where floating is on.</li>
  <li>Select <UI>Preview impact</UI> and read the counts.</li>
  <li>
    Select <UI>Publish to schedule</UI>.
    <span class="step-note">Tick the confirmation if anyone is being cancelled.</span>
  </li>
</Steps>

## What you'll see

The preview runs the publish and rolls it back, so the counts are exact.

## Rules that apply

- **A shift already running or past is never touched**: it is a payroll record.
  See [The operating calendar](/system/calendar).
- **A season sets its own weekly cap**, soft or hard, so do not assume the school year's
  figure. See [Hours, caps, and attribution](/system/hours-rules).
- **Season floating never enters Harnwell**, because only its own workers are trained
  there. See [Floating](/system/floating).

## If it goes wrong

**The range overlaps existing dates.** They belong to a semester, a break, or another
season. Narrow yours.

**Another apply or preview is running.** Nothing was attempted. Wait and run it again.
