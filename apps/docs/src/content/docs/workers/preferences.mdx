Preferences tell your manager which hours you want next term, before the schedule is built.

## Do it

<Steps>
  <li>
    Open <UI>Preferences</UI>.
    <span class="step-note">It lives under <UI>More</UI>.</span>
  </li>
  <li>
    Pick a mode: <UI>Preferred</UI>, <UI>Available</UI>, or <UI>Cannot</UI>.
    <span class="step-note">
      Preferred means you want the hour. Available means you'll take it if needed.
    </span>
  </li>
  <li>Press and drag across blocks to mark them.</li>
  <li>
    Set <UI>Target weekly hours</UI>.
    <span class="step-note">
      Want none? Tick <UI>I have no hours this week</UI> instead.
    </span>
  </li>
  <li>Tap <UI>Save</UI>.</li>
</Steps>

## What you'll see

Your marks stay put. Change them any time until the deadline.

Until you submit, reminders arrive 5, 3, and 1 day before it.

## Rules that apply

- **Opting out is not final.** Your manager assigns you nothing, but you can still claim
  open shifts all period.
- **A blank block counts as "cannot."** The first build pass offers only hours you marked,
  so mark everything you can work. See [Core concepts](/system/concepts).
- **Marks lock at the deadline.** Building starts then, so a later change is your manager's.
  See [The operating calendar](/system/calendar).
- **Your marks are input, not a promise.** Your manager can override a "cannot" after
  confirming it, so flag anything impossible.
- **The target only guides the build.** Pick any number up to 20 in the school year;
  summer sets its own cap. See [Hours, caps, and attribution](/system/hours-rules).

## If it goes wrong

**No deadline set for this period.** Nothing is open yet.

**Save refused after the deadline.** The window closed, but your manager can enter
preferences for you.

**A prompt when you leave.** You have unsaved edits. Nothing is stored until you tap
<UI>Save</UI>.
