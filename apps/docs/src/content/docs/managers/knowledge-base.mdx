The knowledge base is the only source the desk assistant answers from. Nothing enters it
until you approve it.

<Callout label="Who may approve">
  HM, BA, RSM, and Administrator may approve; an SM cannot. The authority covers all 13
  houses, not only yours, because the corpus is one shared rule set with a small per-house
  overlay.
</Callout>

## Do it

<Steps>
  <li>
    Open <UI>Knowledge base</UI> under <UI>Manage</UI>.
  </li>
  <li>
    Upload the file into <UI>Upload documents</UI>.
    <span class="step-note">Markdown, plain text, or PDF.</span>
  </li>
  <li>
    Open the row in <UI>Intake queue</UI> and read the proposal against the document.
  </li>
  <li>
    Correct the house scope, sensitivity, and validity dates.
  </li>
  <li>
    Select <UI>Approve and index</UI>, or <UI>Reject</UI>.
  </li>
</Steps>

## What you'll see

An approved document is answerable at once and cited as a source.

## Rules that apply

- **Sensitivity and house scope decide who gets the answer.** Someone outside the scope
  gets no hint the item exists, so an over-broad scope is a disclosure.
  [Roles and the duty hierarchy](/system/roles)
- **Date-bound rules need their dates.** Retrieval is as of the date asked about, so an
  undated rule never expires.
  [Asking the desk assistant](/workers/assistant)
- **Incidents enter only as a de-identified lesson.** Disciplinary and private ones produce
  none, because raw text never enters the index.

## If it goes wrong

**A "Managers only" notice.** You hold SM or SW only; ask an HM, BA, or RSM.

**The row reads failed.** The row carries the reason. Fix the file and upload again.

**A live document is wrong.** Use <UI>Delete document</UI>; retrieval stops at once. Reject
only ends a proposal that never went live.
