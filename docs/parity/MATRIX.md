## My Shifts (3 tabs + Drop sheet)

> The My Shifts surface is visually complete and faithful to the design: the three spec tabs (My Shifts / Open in My House / Open in Other Houses) render with the correct top-to-bottom subsection order (picked-up, dropped, scheduled), always-rendering ShiftSection containers with empty placeholders, a week-total hours chip, per-state card treatments, and a Drop sheet with occurrence/permanent scope radios + short-notice warning + destructive confirm. The pure decision surface (shifts/Shifts.kt + MyShiftPresentation.kt) is thoroughly unit-tested (ShiftsScreenViewModelTest, 30+ cases) and the read path is wired (worker_my_shifts view via WorkerShiftsRepository). The dominant gap is WRITES: drop/reclaim are optimistic-local section moves in the ViewModel (ShiftsScreenViewModel.kt:115-123) with NO Edge-Function call, even though drop-shift / permanent-drop EFs exist — the mobile data layer (WorkerShiftsRepository) has read methods only, no write/invoke. Two further data blockers are real and confirmed: the Dropped-still-open section can never populate because dropped_still_open is hard-coded false in the read-model view (20260605000001_worker_read_model_views.sql:50), and the week-total/claim hours meter is fed DemoData.DEMO_WEEKLY_HOURS (MainActivity.kt:121,235), not a real computed figure. PROGRESS self-reports (DESIGN_TOKENS §6 row 1 & 5) that drop/claim are optimistic-local and dropped_still_open is hard-coded false — both VERIFIED against current code; the in-flight wiring on this branch (PreferencesRepository, worker_read_scheduling_periods) is for Preferences, not My Shifts, so it does not change this surface.

## Open Shifts (My House / Other Houses) + Claim flow

> The Open Shifts surface is visually and structurally complete and its PURE decision surface is genuinely well-built and well-tested: feed split (weekly/permanent), home-vs-other-house grouping, T-2h unpickable gate, soft/hard cap verdicts, and the claim hours meter all live in tested shared logic (OpenShiftPresentation.kt / Shifts.kt) with strong kotlin.test coverage, and the full backend (claim-shift EF, claim_open_shift + claim_hours_projection RPCs, worker_open_shifts view with the Harnwell cross-house matrix) exists and is pgTAP-tested. The load-bearing gap is WIRING: ShiftsScreenViewModel.claim() (lines 100-113) is an optimistic local section-move that NEVER calls the claim-shift EF — grep for claim-shift/claim_open_shift/functions.invoke across apps/mobile/shared/src returns zero hits — so caps, T-2h, cross-house eligibility, time-conflict, and FCFS conflict resolution are all gated only client-side with no server write. Two further notes: (1) the design's partial-coverage "How much can you cover?" block-range trim has NO basis in spec §5.3 (the spec only describes partial DROP §5.2, not partial CLAIM) and is correctly omitted from the build — a design-vs-spec deviation that the build resolved toward the spec; (2) permanent pickup is wired to a backend that returns 501 not_implemented.

## Float Acknowledgment (pending / ack / declined / deadline)

> The float-ack hero UI is fully built and visually faithful (Compose FloatAcknowledgmentScreen.kt + iOS FloatAcknowledgmentView.swift), driven entirely by shared, well-tested pure logic (FloatAckPresentation.kt, Ack.kt, AckDeclineViewModel.kt; 22 kotlin.test cases). Every "swap" token in the mobile codebase is incidental: an SVG icon path in the design HTML, a SWAP _notification category_ (so a swap-request push can render in the Updates feed), and unrelated comment prose. The design HTML itself contains no swap-action modal or propose-swap flow — only the decorative icon and the notification category — so this is primarily an upstream design gap as well as an implementation gap. There is no Maestro e2e and no kotlin.test covering a swap flow; the lone swap test asserts notification-category mapping only. Closing this requires designing the swap-initiation/accept/reject UX, building UI on both platforms, a shared swap ViewModel + repository wired to the four Edge Functions, and tests — an XL effort.
